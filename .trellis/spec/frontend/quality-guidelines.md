# 质量规范

> 当前项目使用 Vitest、Vue Test Utils、`vue-tsc` 和 Vite 构成最小质量门禁。

---

## 测试分层

### 领域逻辑单元测试

[src/domain/score.test.ts](../../../src/domain/score.test.ts) 直接测试纯函数：

- 空集合的平均分为 `0`。
- 多条成绩能够计算平均分。
- 非空集合能够找到最高分记录。
- 空集合不存在最高分记录。

新增领域函数或修改统计规则时，优先在相邻领域测试中覆盖边界值。

### 页面组件测试

[src/App.test.ts](../../../src/App.test.ts) 使用 Vue Test Utils 和 jsdom 验证用户可观察行为：

- 初始学生人数、平均分和最高分正确展示。
- 填写并提交表单后列表增加一行。
- 新记录保留默认科目和输入成绩。
- 页面人数同步更新。

组件测试断言页面行为和语义，不断言内部 `ref`、函数名或 Tailwind class。

## 验证命令

```bash
# 运行全部测试
pnpm test

# 监听测试
pnpm run test:watch

# TypeScript 检查和生产构建
pnpm run build
```

## 必须遵循

- 新增纯函数时补充单元测试。
- 修改可观察交互时补充或更新组件测试。
- 修复缺陷时先增加能复现问题的回归测试。
- 测试数据应只包含理解行为所需的字段和值。
- Registry 组件升级后至少运行组件测试和构建。
- 提交前按“测试 → 类型检查与构建”的顺序验证。

## 避免

- 不写删除实现后仍会通过的空洞测试。
- 不通过快照替代关键行为断言。
- 不在测试中复制生产统计逻辑来生成期望值。
- 不用类型断言或忽略指令隐藏测试环境中的真实错误。
- 不为了让检查通过而吞掉异常或添加静默兜底。

## 审核清单

- [ ] 改动符合当前领域类型和目录职责。
- [ ] 没有重复的科目、统计或校验逻辑。

- [ ] shadcn-vue 组件通过公共入口导入且无未使用组件。
- [ ] 相关测试覆盖正常路径和必要边界。
- [ ] `pnpm test` 通过。
- [ ] `pnpm run build` 通过。
- [ ] 新出现的长期规则已经评估是否需要更新 Spec。
