# 质量规范

> 当前项目使用 Vitest、Vue Test Utils、`vue-tsc` 和 Vite 构成最小质量门禁。

---

## 测试分层

### 领域逻辑单元测试

[src/domain/expense.test.ts](../../../src/domain/expense.test.ts) 直接测试纯函数：

- 空列表的总额为 `0`。
- 多条记录的金额能够被累加。

新增领域函数或修改计算规则时，优先在相邻的领域测试中覆盖边界值。

### 页面组件测试

[src/App.test.ts](../../../src/App.test.ts) 使用 Vue Test Utils 和 jsdom 验证用户可观察行为：

- 填写并提交表单。
- 列表增加一行。
- 新记录显示为“待审批”。
- 页面数量同步更新。

组件测试断言页面行为和语义，不断言内部 `ref`、函数名或 CSS 实现细节。

## 验证命令

```bash
# 运行全部测试
pnpm test

# 监听测试
pnpm run test:watch

# TypeScript 检查和生产构建
pnpm run build
```

## 必须遵循

- 新增纯函数时补充单元测试。
- 修改可观察交互时补充或更新组件测试。
- 修复缺陷时先增加能复现问题的回归测试。
- 测试数据应只包含理解行为所需的字段和值。
- 提交前按“测试 → 类型检查与构建”的顺序验证。

## 避免

- 不写删除实现后仍会通过的空洞测试。
- 不通过快照替代关键行为断言。
- 不在测试中复制生产计算逻辑来生成期望值。
- 不用类型断言或忽略指令隐藏测试环境中的真实错误。
- 不为了让检查通过而吞掉异常或添加静默兜底。

## 审核清单

- [ ] 改动符合当前领域类型和目录职责。
- [ ] 没有重复的状态、常量或计算逻辑。
- [ ] 用户输入在进入领域对象前完成校验。
- [ ] 相关测试覆盖正常路径和必要边界。
- [ ] `pnpm test` 通过。
- [ ] `pnpm run build` 通过。
- [ ] 新出现的长期规则已经评估是否需要更新 Spec。
